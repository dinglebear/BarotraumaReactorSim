Making a sub from the repository

The command line edits real .sub files: it places items out of walls, routes wires along the ceilings, checks circuit boxes against the game's limits and renders a picture after every change. SUBBUILD.md and SUBEDIT.md have the details.

Change a vanilla sub

# write a patch: add items, wire them, drop in circuit boxes
add @btn button at -900,120
box @brain at -950,100 from circuits/my_brain.circ
wire @btn.signal_out @brain.signal_in1

# apply it, then look at what you made
node sim/cli.js sub patch Dugong my_patch
node sim/cli.js sub render My_Dugong --base Dugong

The render shows the true hull and every new item and wire in orange. sub audit lists anything loose, inside a wall or over a box's 64-part limit.

Test it like a round

# a practice round with the sub's own circuits
node sim/cli.js ship My_Dugong --transcript

# one circuit on its own, with scripted inputs
node sim/cli.js sandbox text_display

# everything, including Camel Overkill's round
npm test

The transcript prints radio chat, terminal lines and every text display, and warns about displays nobody could read.

Rules come from Barotrauma's published source code (FakeFishGames/Barotrauma) and are noted in reference/. Textures aren't part of that code, so subs are drawn from their collision shapes, rooms and items. Built by Claude with Dinglebear, who tests it in game.
